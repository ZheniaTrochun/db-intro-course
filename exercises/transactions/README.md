## Що таке транзакція?

Транзакція - це набір запитів, що виконуються як одна неподільна логічна операція:
застосовуються або всі зміни разом, або жодна з них.

```sql
BEGIN;

UPDATE account_balance SET balance = balance - 100 WHERE account_id = 1;
UPDATE account_balance SET balance = balance + 100 WHERE account_id = 2;

COMMIT;
```

Якщо між цими двома `UPDATE` станеться помилка чи збій - жодна зі змін не застосується
(достатньо виконати `ROLLBACK` замість `COMMIT`).

| Команда    | Опис                                                                       |
|------------|------------------------------------------------------------------------------|
| `BEGIN`    | Початок транзакції                                                          |
| `COMMIT`   | Збереження усіх змін транзакції                                             |
| `ROLLBACK` | Відкат транзакції - база даних повертається до стану до початку транзакції  |

## Навіщо потрібні транзакції?

- гарантують цілісність даних, коли одна логічна операція вимагає кількох SQL-запитів;
- дозволяють відкотити зміни у разі помилки, втрати з'єднання чи порушення обмежень (constraints);
- забезпечують коректну роботу паралельних процесів, що працюють з одними й тими ж даними.

## Властивості ACID

- **Atomicity (атомарність)** - усі операції транзакції виконуються повністю або не виконуються зовсім.
- **Consistency (консистентність)** - транзакція переводить БД з одного коректного стану в інший
  (жодні `PRIMARY KEY`, `FOREIGN KEY`, `CHECK` не порушуються).
- **Isolation (ізоляція)** - паралельні транзакції не повинні непередбачувано впливати одна на одну.
- **Durability (персистентність)** - після `COMMIT` зміни гарантовано не будуть втрачені.

## Типові проблеми паралельних транзакцій

| Проблема              | Опис                                                                          |
|------------------------|--------------------------------------------------------------------------------|
| Dirty write            | Транзакція перезаписує ще незбережені зміни іншої транзакції                  |
| Dirty read             | Транзакція читає дані, які інша транзакція ще не закомітила                   |
| Non-repeatable read    | Повторне читання того ж рядка в межах транзакції повертає інше значення       |
| Phantom read           | Повторний `SELECT` повертає нові (або зниклі) рядки, яких не було раніше      |
| Lost update            | Дві транзакції читають та змінюють одні й ті ж дані - результат однієї "губиться" |
| Write skew             | Дві транзакції паралельно перевіряють умову й обидві діють на її основі, що в сумі порушує цю умову |

## Рівні ізоляції в PostgreSQL

Чим вищий рівень ізоляції - тим менше проблем із конкурентним доступом, але тим повільніша робота.

| Рівень                                | Уникає                                              |
|-----------------------------------------|--------------------------------------------------------|
| Read Committed (за замовчуванням)     | Dirty read, dirty write                               |
| Repeatable Read                        | + Non-repeatable read, lost update, phantom read       |
| Serializable                           | + Write skew (повна ізоляція)                          |

```sql
BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

## SELECT ... FOR UPDATE

Альтернатива підвищенню рівня ізоляції - явно заблокувати конкретні рядки для оновлення.
Корисно для сценаріїв "прочитати -> змінити -> записати" (read-modify-write).

```sql
BEGIN;

SELECT * FROM users WHERE id = 10 FOR UPDATE;   -- блокує рядок до кінця транзакції

UPDATE users SET balance = balance + 100 WHERE id = 10;

COMMIT;
```

`FOR UPDATE` блокує інші `UPDATE`, `DELETE` та `SELECT ... FOR UPDATE` над цим рядком
(звичайний `SELECT` без блокування не блокується).

## Практичні поради

- Використовуйте транзакції для будь-якої операції, що складається з кількох запитів, які мають
  застосовуватись разом.
- Обирайте найнижчий рівень ізоляції, достатній для задачі - зазвичай вистачає `Read Committed`.
- Для read-modify-write сценаріїв - `SELECT ... FOR UPDATE` часто простіший за підвищення ізоляції.
- Не забувайте про `ROLLBACK`, якщо перевірка умов усередині транзакції не пройшла - інакше
  транзакція "зависне" відкритою.
