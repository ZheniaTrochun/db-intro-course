# Звіт до лабораторної роботи 3

## Тема роботи

Робота з реляційною базою даних засобами SQL: створення таблиць, додавання, вибірка, оновлення та видалення даних.

## Мета роботи

Навчитися:

- створювати таблиці та зв'язки між ними;
- використовувати первинні та зовнішні ключі;
- додавати записи за допомогою `INSERT`;
- отримувати дані за допомогою `SELECT` і `JOIN`;
- змінювати дані за допомогою `UPDATE`;
- видаляти дані за допомогою `DELETE`;
- використовувати обмеження цілісності даних.

## Структура бази даних

У базі даних створено такі таблиці:

- `dorms` — гуртожитки;
- `users` — користувачі;
- `departments` — кафедри;
- `rooms` — кімнати;
- `students` — студенти;
- `dorm_admins` — адміністратори гуртожитків;
- `parking_slots` — паркомісця;
- `courses` — навчальні курси;
- `enrollments` — записи студентів на курси;
- `vacancies` — вакансії;
- `applications` — заяви студентів на вакансії.

Для статусів створено перелічувані типи:

- `student_status`;
- `user_status`;
- `application_status`.

### Особливість зв'язку користувача і студента

Гуртожиток зберігається тільки в таблиці `users` у полі `dorm_id`.
У таблиці `students` зберігається лише кімната в полі `room_id`.
Зв'язок студента з користувачем реалізовано через `students.user_id`.

Обмеження `UNIQUE` для `students.user_id` гарантує, що один користувач може мати
не більше одного запису в таблиці студентів. Зовнішній ключ `students.room_id`
гарантує, що призначена кімната існує в таблиці `rooms`.

## Вибірка даних (`SELECT`)

У скрипті виконуються такі вибірки:

1. Активні користувачі разом із номерами їхніх гуртожитків.
2. Студенти, які проживають у кімнатах.
3. Вільні паркомісця.
4. Курси, кафедри та кількість записаних студентів.
5. Заяви на вакансії разом із даними студента та вакансії.
6. Перевірка доданої заяви на вакансію `SoftServe`.
7. Перевірка доданого користувача Ірини Левченко.
8. Перевірка статусу заяви Івана Петренка до та після оновлення.
9. Перевірка кімнати, призначеної користувачу з `user_id = 8`.
10. Перевірка наявності вакансії після її видалення.
11. Перевірка видалення користувача.
12. Перевірка видалення вільного паркомісця.

Для отримання номера гуртожитку студента використовується зв'язок:

```sql
JOIN users u ON u.user_id = s.user_id
JOIN dorms d ON d.dorm_id = u.dorm_id
```

Таким чином, значення `dorm_id` не дублюється в таблиці `students`.

## Зміна даних (`UPDATE`)

### Зміна статусу заяви

Статус заяви Івана Петренка на вакансію `EPAM` змінюється з `submitted`
на `accepted`:

```sql
UPDATE applications
SET status = 'accepted'
WHERE student_id = (SELECT student_id FROM students WHERE user_id = 1)
  AND vacancy_id = (
      SELECT vacancy_id
      FROM vacancies
      WHERE company_name = 'EPAM'
  );
```

### Призначення гуртожитку та кімнати

Для користувача з `user_id = 8` виконуються два `UPDATE`, оскільки змінюються
поля у двох різних таблицях:

```sql
UPDATE users
SET dorm_id = 3
WHERE user_id = 8;

UPDATE students
SET room_id = 5
WHERE user_id = 8;
```

Перший запит змінює гуртожиток користувача, а другий — кімнату студента.
`dorm_id` у таблиці `students` відсутній, тому він не дублюється.

## Видалення даних (`DELETE`)

### Видалення вакансії

Вакансія `Rozetka` видаляється за назвою:

```sql
DELETE FROM vacancies
WHERE company_name = 'Rozetka';
```

Оскільки таблиця `applications` має зовнішній ключ із `ON DELETE CASCADE`,
пов'язана із цією вакансією заява видаляється автоматично.

### Видалення користувача

Користувач Ірина Левченко видаляється за електронною поштою:

```sql
DELETE FROM users
WHERE email = 'iryna.levchenko@example.com';
```

У користувача немає пов'язаних записів, тому видалення виконується успішно.

### Видалення вільного паркомісця

Наприкінці видаляється вільне паркомісце `P-401`:

```sql
DELETE FROM parking_slots
WHERE slot_number = 'P-401'
  AND user_id IS NULL;
```

Умова `user_id IS NULL` гарантує, що видаляється лише паркомісце,
яке не закріплене за користувачем.

## Висновок

У лабораторній роботі створено базу даних для обліку гуртожитків, користувачів,
студентів, кімнат, курсів, вакансій і заяв. Виконано операції додавання,
вибірки, оновлення та видалення даних.

Для уникнення дублювання `dorm_id` гуртожиток зберігається тільки в таблиці
`users`, а студент пов'язується з користувачем через `user_id`. Це дозволяє
отримувати гуртожиток студента через `JOIN` і зберігати структуру бази даних
більш узгодженою.
