### 1. Мета роботи
Опанування основних операцій маніпулювання даними (DML) у PostgreSQL в стилі OLTP (онлайн-обробка транзакцій): вибірка даних (`SELECT` із фільтрацією `WHERE`), додавання нових записів (`INSERT`), модифікація існуючих рядків (`UPDATE` із використанням `SET` та `WHERE`) та безпечне видалення даних (`DELETE`), а також перевірка дотримання обмежень цілісності (`CHECK`, `UNIQUE`, зовнішніх ключів).

---

### 2. Специфікація виконаних DML-операцій

У ході тестування фізичної схеми бази даних `clothing_store_db` було виконано серію транзакційних запитів:

| № | Операція | Цільова таблиця | Мета запиту | Умова фільтрації (`WHERE`) | Очікуваний та фактичний результат |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1.1 | `SELECT` | `customer` | Отримання контактних даних усіх клієнтів (вибір конкретних стовпців) | — | Успішно повернуто імена, прізвища та email усіх зареєстрованих покупців |
| 1.2 | `SELECT` | `product` | Пошук товарів преміум-сегменту (вартістю від 1000 грн) | `product_price >= 1000` | Успішно відфільтровано джинсову куртку та джинси |
| 1.3 | `SELECT` | `"order"` | Отримання активних замовлень у процесі обробки | `order_status = 'Processing'` | Успішно виведено замовлення зі статусом `'Processing'` |
| 2.1 | `INSERT` | `category` | Додавання нової категорії товарів («Аксесуари») | — | Успішно створено запис із автоматично згенерованим `category_id` |
| 2.2 | `INSERT` | `customer` | Реєстрація нового клієнта в системі | — | Успішно додано нового покупця з унікальним `email` |
| 2.3 | `INSERT` | `product` | Додавання нового товару до категорії «Аксесуари» | — | Успішно додано товар із прив'язкою до нового `category_id` |
| 2.4 | `INSERT` | `payment` | Фіксація оплати для раніше неоплаченого замовлення №3 | — | Успішно проведено транзакцію оплати (`Cash on Delivery`) |
| 3.1 | `UPDATE` | `customer` | Оновлення email та номера телефону клієнта | `first_name` та `last_name` | Успішно змінено контактні дані конкретного клієнта |
| 3.2 | `UPDATE` | `product` | Коригування (підвищення) ціни товару | `product_name = 'Шкіряний ремінь Classic'` | Ціну товару успішно оновлено з `650.00` до `699.00` |
| 3.3 | `UPDATE` | `"order"` | Зміна статусу замовлення №3 після отримання оплати | `order_id = 3` | Статус успішно змінено з `'Pending'` на `'Processing'` |
| 4.1 | `DELETE` | `product` | Безпечне видалення тестового товару після перевірки через `SELECT` | `product_name = 'Шкіряний ремінь Classic'` | Рядок успішно видалено без порушення посилальної цілісності |

### 3. SQL-скрипт маніпулювання даними (DML)

```sql

-
-- 1.  SELECT 


--  Вибірка конкретних стовпців із таблиці клієнтів
SELECT first_name, last_name, email 
FROM customer;

-- Фільтрація товарів вартістю від 1000 грн
SELECT product_name, product_price 
FROM product 
WHERE product_price >= 1000;

-- Пошук замовлень у статусі обробки
SELECT order_id, customer_id, order_date, order_price, order_status 
FROM "order" 
WHERE order_status = 'Processing';



-- 2.  INSERT 


--  Додавання нової категорії
INSERT INTO category (category_name) 
VALUES ('Аксесуари');

-- Реєстрація нового клієнта
INSERT INTO customer (first_name, last_name, email, phone) 
VALUES ('Олександр', 'Петренко', 'oleksandr.petrenko@example.com', '+380634445566');

-- Додавання нового товару в створену категорію (category_id = 4)
INSERT INTO product (category_id, product_name, product_description, product_price) 
VALUES (4, 'Шкіряний ремінь Classic', 'Ремінь з натуральної шкіри', 650.00);

-- Додавання платежу для замовлення №3
INSERT INTO payment (order_id, payment_date, payment_amount, payment_method) 
VALUES (3, '2026-10-28 09:05:00', 499.00, 'Cash on Delivery');

-- Перевірка результатів вставки:
SELECT * FROM category;
SELECT * FROM customer;
SELECT * FROM product WHERE category_id = 4;
SELECT * FROM payment;



-- 3. UPDATE 


-- Попередня перевірка запису перед оновленням:
SELECT * FROM customer WHERE first_name = 'Олександр' AND last_name = 'Петренко';

-- Оновлення контактних даних клієнта
UPDATE customer 
SET email = 'oleksandr.new@example.com', phone = '+380995556677'
WHERE first_name = 'Олександр' AND last_name = 'Петренко';

-- Зміна ціни тестового товару
UPDATE product 
SET product_price = 699.00 
WHERE product_name = 'Шкіряний ремінь Classic';

-- Оновлення статусу оплаченого замовлення №3
UPDATE "order" 
SET order_status = 'Processing' 
WHERE order_id = 3;

-- Перевірка результатів оновлення:
SELECT * FROM customer WHERE first_name = 'Олександр';
SELECT * FROM product WHERE product_name = 'Шкіряний ремінь Classic';
SELECT * FROM "order" WHERE order_id = 3;



-- 4. DELETE 


-- Попередня перевірка рядка перед видаленням:
SELECT * FROM product WHERE product_name = 'Шкіряний ремінь Classic';

-- Видалення тестового товару 
DELETE FROM product 
WHERE product_name = 'Шкіряний ремінь Classic';

-- Перевірка стану таблиці після видалення:
SELECT * FROM product;
```

### 4. Дотримання правил безпеки та цілісності даних

1. **Обов'язкове використання `WHERE`:** У всіх операціях `UPDATE` та `DELETE` застосовано чіткі умови фільтрації за унікальними або ідентифікуючими атрибутами, що виключає ризик випадкової модифікації чи видалення всіх записів у таблиці.
2. **Попередня верифікація через `SELECT`:** Перед виконанням критичних змін (`UPDATE` та `DELETE`) виконувалися тестові вибірки `SELECT` із аналогічною умовою `WHERE` для підтвердження коректності вибору цільових рядків.
3. **Перевірка посилальної цілісності:** Додавання товару до нової категорії та платежу до існуючого замовлення підтвердило коректну роботу зовнішніх ключів (`REFERENCES`) та автоматичної генерації ідентифікаторів (`GENERATED ALWAYS AS IDENTITY`).
