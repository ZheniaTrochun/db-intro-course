# Лабораторна робота 5. Нормалізація бази даних

## Мета роботи

Показати на прикладах, як порушення 1НФ, 2НФ і 3НФ призводять до дублювання даних та як повернутися до нормалізованої схеми.

## Що зроблено

У початковій схемі тенісного клубу вже використовуються окремі таблиці для бронювань, кортів та інвентарю. У `normalize-existing.sql` я тимчасово додаю зайві поля, показую дані запитами `SELECT`, а потім видаляю ці поля.

- **1НФ.** Тимчасово зберігаю кілька ID інвентарю в одному полі booking.equipment_ids. У робочій схемі кожна позиція інвентарю має окремий рядок у booking_equipment.
- **2НФ.** Тимчасово додаю назву інвентарю до booking_equipment. Вона залежить тільки від equipment_id, який є частиною складеного ключа. Назва зберігається в таблиці equipment.
- **3НФ.** Тимчасово додаю назву корта до booking. Назва визначається через court_id, тому зберігається в таблиці court.

Також у схемі є таблиця equipment_category. Вона зберігає назви категорій інвентарю, а поле equipment.category посилається на неї через зовнішній ключ.

## Файли

- schema.sql — створює таблиці підсумкової схеми.
- categories.sql — додає до equipment_category категорії racket і balls.
- normalize-existing.sql — демонструє приклади порушень 1НФ, 2НФ і 3НФ. Наприкінці команда ROLLBACK скасовує всі тимчасові зміни.

## Порядок запуску

1. Виконати schema.sql.
2. Виконати categories.sql.
3. Завантажити тестові дані з seed.sql лабораторної роботи 2.

Після цього виконати normalize-existing.sql, щоб побачити демонстрацію нормальних форм. Для роботи цього скрипту в таблицях мають бути тестові записи, зокрема бронювання з ID 1 та інвентар із ID 1 і 3.

Якщо тестові дані з лабораторної роботи 2 вже завантажені, для демонстрації достатньо виконати `normalize-existing.sql`.

## Очікуваний результат

У виводі запитів видно, що кілька ID інвентарю тимчасово записані в одному полі, а в робочій схемі інвентар зберігається окремими рядками з кількістю. Також видно назви інвентарю та кортів, отримані з відповідних таблиць.

Після виконання `ROLLBACK` тимчасові поля зникають, а початкові дані залишаються без змін.
