# ТЗ: Лабораторна робота 5 — Нормалізація БД

## Мета
Проаналізувати схему з лаб. 2, знайти надлишковість та аномалії, визначити функціональні залежності й нормалізувати таблиці до **3NF**.

## Що зробити

1. **Аналіз схеми**
   - відкрити схему з лаб. 2 у PostgreSQL, переглянути таблиці, стовпці, зразки даних;
   - знайти погано структуровані таблиці: повторювані групи, дублювання значень, ознаки аномалій вставки/оновлення/видалення.

2. **Функціональні залежності (ФЗ)**
   - для кожної проблемної таблиці записати ФЗ у вигляді `X -> Y`;
   - визначити всі ключі та залежність від них неключових стовпців;
   - для початкової схеми набір ФЗ має бути **коректним, повним, мінімальним**.

3. **Перевірка нормальних форм** (для початкової схеми вказати найвищу НФ і пояснити)

   | НФ | Умова | Що порушує |
   |----|-------|------------|
   | **1NF** | усі атрибути атомарні | повторювані групи, списки в одному стовпці |
   | **2NF** | 1NF + немає залежності від *частини* складеного ключа | часткові залежності |
   | **3NF** | 2NF + неключовий атрибут не залежить від іншого неключового | транзитивні залежності |

4. **Нормалізація** (покроково: 1NF → 2NF → 3NF)
   - 1NF: винести повторювані групи в нові таблиці;
   - 2NF: декомпозиція для усунення часткових залежностей;
   - 3NF: декомпозиція для усунення транзитивних залежностей;
   - на кожному кроці показати: вихідну таблицю, нові таблиці (з ключами), чому це усуває аномалію;
   - за потреби додати сурогатні ключі або довідникові таблиці.

5. **Нові DDL**
   - `CREATE TABLE` для всіх таблиць у 3NF: стовпці, типи, PK, FK;
   - за потреби `DROP TABLE`;
   - перевірити в pgAdmin / psql.

6. **Нова діаграма**
   - намалювати схему після нормалізації, експортувати в зображення або PDF;
   - усі нові таблиці та зв'язки мають бути на діаграмі.

7. **Перевірка після змін**
   - перезавантажити зразкові дані;
   - переконатися, що FK працюють, а запити повертають правильні результати.

## Поради

- **Часткова залежність**: неключовий атрибут залежить лише від частини складеного ключа.
- **Транзитивна залежність**: неключовий атрибут залежить від іншого неключового.
- Надмірна декомпозиція шкодить продуктивності; мета: **3NF** (або BCNF), якщо немає причини зупинитися раніше.

## Критерії оцінювання

- **ФЗ**: наведено всі ФЗ початкової схеми, вони коректні, повні й мінімальні.
- **Початкова НФ**: вказано найвищу НФ вихідної схеми, пояснено порушення (часткові / транзитивні залежності).
- **Етапи**: показано всі кроки 1NF → 2NF → 3NF; кожен проміжний етап містить таблиці з атрибутами та ключами; фінал у 3NF.
- **DDL**: скрипти для фінальних таблиць із правильними стовпцями, типами, PK та FK.
