## 1. Мета роботи
Опанувати написання оперативних транзакційних запитів (OLTP) для маніпулювання даними (DML): реалізувати вибірки з фільтрацією та об'єднанням таблиць, точкове додавання записів через `RETURNING`, безпечні оновлення даних, перевірку політик посилальної цілісності (`RESTRICT`, `CASCADE`, `SET NULL`) та комплексну ACID-транзакцію.

## 3. Огляд реалізованих запитів

### 1. Операції читання (SELECT)
- **1.1. Контактний довідник клієнтів:** вибірка реквізитів юридичних осіб (`company_name`, `contact_person`, `phone`, `email`) із сортуванням за алфавітом.
- **1.2. Фільтрація угод у воронці:** вибірка угод на етапах переговорів та підписання договору (`negotiation`, `contract`) із сортуванням за спаданням суми.
- **1.3. Звіт по виграних угодах (JOIN):** реляційне об'єднання `deals`, `clients` та `users` для виведення реалізованих угод із зазначенням імен менеджерів та контрагентів.
- **1.4. Деталізація складу угоди (M:N):** вибірка позицій замовлення з `deal_products`, розрахунок вартості рядка (`quantity * actual_price`) та зіставлення фактичної ціни з базовою каталожною ціною.
- **1.5. Оперативні завдання менеджерів:** вибірка активних завдань (`pending`) для конкретних виконавців із сортуванням за дедлайном.

### 2. Додавання даних (INSERT)
- **2.1. Додавання нового клієнта:** реєстрація корпоративного клієнта з поверненням згенерованого PK через конструкцію `RETURNING`.
- **2.2. Додавання нової послуги:** внесення нової сервісної позиції в каталог продуктів із поверненням атрибутів.
- **2.3. Створення нової угоди:** реєстрація угоди для доданого клієнта із закріпленням відповідального менеджера.
- **2.4. Наповнення угоди товарами:** додавання кількох товарних позицій у проміжну таблицю `deal_products`.

### 3. Модифікація даних (UPDATE)
- **3.1. Оновлення контактних даних клієнта:** безпечне оновлення телефону та ПІБ контактної особи з обов'язковою умовою `WHERE id = ...`.
- **3.2. Просування угоди по воронці:** переведення угоди зі статусу `new` у `negotiation` з оновленням часової мітки `updated_at`.
- **3.3. Виконання завдання:** зміна стану оперативного завдання з `pending` на `completed`.
- **3.4. Автоматичний перерахунок суми угоди:** агрегований `UPDATE` поля `total_amount` у таблиці `deals` на основі суми вартостей позицій з `deal_products`.

### 4. Видалення та перевірка цілісності (DELETE)
- **4.1. Безпечне видалення завдання:** видалення виконаного завдання за його первинним ключем.
- **4.2. Перевірка CASCADE та SET NULL:** створення тестової угоди із позиціями й завданням, її видалення та підтвердження, що пов'язані позиції видалилися автоматично (CASCADE), а в завданні зовнішній ключ скинувся в `NULL` (SET NULL).
- **4.3. Перевірка RESTRICT:** перевірка блокування видалення менеджера, за яким закріплені угоди (СУБД перехоплює помилку зовнішнього ключа).

### 5. Комплексна транзакція (ACID)
- Оформлення комерційної угоди для клієнта «Київстар» у межах єдиного неподільного блоку `BEGIN ... COMMIT`:
  1. Створення угоди у воронці;
  2. Додавання двох товарних позицій;
  3. Призначення нагадування відповідальному менеджеру;
  4. Автоматична фіксація події створення у системному журналі аудиту `audit_logs`.
