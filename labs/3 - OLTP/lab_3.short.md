# ТЗ: Лабораторна робота 3 — SQL DML (PostgreSQL, OLTP)

## Мета
Протестувати БД з лаб. 1–2 через ручні SQL-запити в pgAdmin: `SELECT`, `INSERT`, `UPDATE`, `DELETE`.

## Що зробити

1. **SELECT**
   - вибрати всі записи (`SELECT * ...`);
   - вибрати конкретні стовпці, без `*`;
   - фільтрація через `WHERE`;
   - додатково: `JOIN` таблиць або фільтр за id студента / кодом курсу (схема студент-курс), замовлення за сумою або клієнти за містом (e-commerce).

2. **INSERT**
   - додати нові рядки в таблиці із зазначенням стовпців і значень;
   - перевірити результат через `SELECT`.

3. **UPDATE**
   - змінити один або кілька стовпців через `SET`;
   - **обов'язково `WHERE`**;
   - перевірити результат через `SELECT`.

4. **DELETE**
   - видалити рядки з `WHERE`;
   - перевірити через `SELECT`, що рядок зник.

5. **Наповнення даних**: у кожній таблиці мінімум **3–5 рядків**.

## Правила безпеки

- `UPDATE` і `DELETE` завжди з `WHERE`.
- Перед зміною або видаленням запустити `SELECT` з тим самим `WHERE`.
- Для масових змін зробити бекап (`SELECT INTO backup_table`).
- Використовувати транзакції та перевіряти результат кожного запиту.

## Що здати

| № | Результат | Вимоги |
|---|-----------|--------|
| 1 | **SQL-скрипт** | усі `SELECT`, `INSERT`, `UPDATE`, `DELETE` по порядку, з коментарями про таблиці |
| 2 | **Короткий звіт** | для кожного запиту: мета, очікуваний результат, чи успішно виконано |
| 3 | **Доказ наповнення таблиць** | частина SQL-файлу або скріншоти (у кожній таблиці 3–5+ рядків) |
| 4 | **Скріншоти pgAdmin** (за бажанням) | таблиці, Query Tool, результати `SELECT *` |

## Критерії оцінювання

- **Правильність**: коректний синтаксис, запити виконуються без помилок.
- **Ефективність**: запити повертають або змінюють саме потрібні дані.
- **Безпека та практики**: правильні `WHERE`, транзакції, перевірка результатів.
- **Чіткість**: зрозумілі коментарі та структурований звіт.
