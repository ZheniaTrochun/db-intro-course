## Схема бази даних

| Таблиця | Стовпці | Ключі |
| --- | --- | --- |
| member | member_id, first_name, last_name, email, phone | PK member_id |
| author | author_id, first_name, last_name | PK author_id |
| book | book_id, title, isbn, publication_year | PK book_id |
| book_author | book_id, author_id | PK (book_id, author_id); FK до book та author |
| loan | loan_id, member_id, book_id, loan_date, due_date, return_date | PK loan_id; FK до member та book |

Один запис `book` — одна книга для видачі. `book_author` реалізує зв'язок M:N між книгами й авторами. `return_date IS NULL` означає відкриту позику. Історія залишається після повернення книги.

Схема з `lab2` забезпечує PK, FK, обов'язкові поля, непорожні імена й назви, формати контактів та ISBN, додатний рік і коректний порядок дат. Частковий індекс `loan_one_open_per_book` забороняє дві відкриті позики однієї книги. `ON DELETE RESTRICT` зберігає пов'язані дані. ISBN необов'язковий і неунікальний; перевіряється формат, а не контрольна сума.

Кожна початкова книга має автора. Загальна автоматична гарантія цього правила відсутня в `lab2`: FK перевіряє наявність батьківського запису, але не зобов'язує книгу мати рядок у `book_author`. У цій роботі авторство додається в одній транзакції з книгою, а видаляється разом із навчальною книгою. Схему попередньої роботи не змінено.

## SQL-додатки та порядок виконання

Потрібні запущений PostgreSQL, користувач із правом створення бази та гілка `lab3` Fork. Каталог здачі — `labs/3 - OLTP/the1nurz`; він містить `lab3` і дві SQL-залежності в сусідній папці `lab2`. Шляхи до SQL нижче наведено від цього каталогу. Створіть нову порожню базу `library_lab3`.

**Порядок для psql:**

1. [lab3/setup.sql](setup.sql) — підключає спочатку [lab2/schema.sql](../lab2/schema.sql), потім [lab2/data.sql](../lab2/data.sql). Окремо ці два файли додатково не запускайте.
2. [lab3/queries.sql](queries.sql) — початкові дані й вибірки Q1–Q8.
3. [lab3/oltp.sql](oltp.sql) — операції D1–D11 з контрольними SELECT, від `BEGIN` до `ROLLBACK`.
4. [lab3/tests.sql](tests.sql) — перевірки T1–T6, також із `ROLLBACK`.
5. Повторно `lab3/queries.sql` — підтвердження, що початкові результати не змінилися.

Команди PowerShell починаються в корені Fork та переходять до каталогу здачі; змініть шлях до `bin` та користувача за потреби. Порт — стандартний 5432, пароль вводиться на запит.

```powershell
Set-Location -LiteralPath 'labs/3 - OLTP/the1nurz'
$pgBin = 'C:\Program Files\PostgreSQL\18\bin'
& "$pgBin\createdb.exe" -h localhost -U postgres library_lab3
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 `
    -f .\lab3\setup.sql -f .\lab3\queries.sql -f .\lab3\oltp.sql `
    -f .\lab3\tests.sql -f .\lab3\queries.sql
```

**Порядок для pgAdmin 4:** відкривайте файли з каталогу `labs/3 - OLTP/the1nurz`. Створіть порожню базу, відкрийте Query Tool з Auto-commit та виконайте `lab2/schema.sql` → `lab2/data.sql` → `lab3/queries.sql` → `lab3/oltp.sql` → `lab3/tests.sql` → повторно `lab3/queries.sql`. `setup.sql` тут не виконується, бо містить команди psql. Вибірки переглядайте по одній у Data Output. Для проміжних результатів D1–D11 виконуйте блоки послідовно в одному Query Tool, почавши з `BEGIN` і закінчивши `ROLLBACK`; тести запускайте всім файлом, повідомлення PASS дивіться в Messages.

Успішний запуск завершується без `ERROR`: вибірки відповідають таблицям результатів нижче, `oltp.sql` змінює по одному рядку за операцію, а `tests.sql` повідомляє `T1 PASS` … `T6 PASS`. Після повторного `queries.sql` зберігаються кількості 5/5/5/6/5 та початкові результати Q1–Q8. Якщо сталася помилка, не переходьте до наступного кроку; у відкритій транзакції виконайте `ROLLBACK;`. Для повторного створення схеми використайте іншу порожню базу.

SQL-файли є додатками до звіту й містять усі оператори в порядку виконання. Необхідні файли `lab2` включено до цієї здачі; PR лабораторної №3 можна перевірити незалежно від PR №2.

| D10 | Видалити навчальну книгу без позик і авторства | PASS: видалено 1 рядок, наступний SELECT порожній |

Кожний `INSERT` має список стовпців і наступний контрольний `SELECT`. Перед кожним `UPDATE` та `DELETE` показано записи з тим самим `WHERE`, після операції — результат. Усього виконано 5 `INSERT`, 4 `UPDATE`, 3 `DELETE`. Кожна зміна зачепила один потрібний рядок.

Демонстрація виконується від `BEGIN` до `ROLLBACK`, тому початкові дані зберігаються. Це навчальна послідовність коротких операцій бібліотекаря; у звичайній роботі завершену бізнес-операцію зберігають через `COMMIT`. Дати фіксовані для повторюваності, ID 1001–1002 призначені для демонстрації.
