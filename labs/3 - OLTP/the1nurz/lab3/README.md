## Запуск через psql у PowerShell

Потрібен запущений PostgreSQL та користувач із правом створення бази. Команди починаються в корені Fork і переходять у каталог здачі `labs/3 - OLTP/the1nurz`. Необхідні `lab2/schema.sql` і `lab2/data.sql` уже включено поруч із `lab3`; окреме прийняття PR лабораторної №2 не потрібне. Укажіть власний шлях до `bin` та користувача замість `postgres`; пароль вводиться на запит. Команди використовують стандартний порт 5432.

```powershell
Set-Location -LiteralPath 'labs/3 - OLTP/the1nurz'
$pgBin = 'C:\Program Files\PostgreSQL\18\bin'
& "$pgBin\createdb.exe" -h localhost -U postgres library_lab3
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 -f .\lab3\setup.sql
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 -f .\lab3\queries.sql
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 -f .\lab3\oltp.sql
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 -f .\lab3\tests.sql
& "$pgBin\psql.exe" -X -h localhost -U postgres -d library_lab3 -v ON_ERROR_STOP=1 -f .\lab3\queries.sql
```

Кожна команда має завершитися без `ERROR`; якщо помилка з'явилася, виправте її перед наступним кроком. Очікувані результати:

- Q2: `member` — 5, `author` — 5, `book` — 5, `book_author` — 6, `loan` — 5; Q6: доступні книги 2 і 5; Q8: прострочені позики 2, 4 і 5.
- `oltp.sql`: 5 повідомлень `INSERT 0 1`, 4 повідомлення `UPDATE 1`, 3 повідомлення `DELETE 1`; після кожного видалення контрольний SELECT порожній.
- `tests.sql`: повідомлення `T1 PASS` … `T6 PASS`. Очікувані порушення обмежень перехоплюються тестами.
- Повторний `queries.sql` після демонстрації й тестів повертає ті самі початкові дані, оскільки зміни відкочено.

`setup.sql` виконується один раз у порожній базі й сам підключає `lab2/schema.sql`, потім `lab2/data.sql`; окремо їх додатково не запускайте. `queries.sql`, `oltp.sql` і `tests.sql` можна повторювати на початкових даних: обидва файли зі змінами завершуються `ROLLBACK`. Для повторного створення таблиць використайте іншу порожню базу.

## Запуск через pgAdmin 4

1. Створіть порожню базу `library_lab3`, відкрийте Query Tool та увімкніть Auto-commit.
2. Із каталогу `labs/3 - OLTP/the1nurz` відкрийте `lab2/schema.sql` і виконайте повністю, потім так само `lab2/data.sql`. Файл `lab3/setup.sql` призначений лише для psql; у цьому способі його пропускаємо.
3. Відкрийте `lab3/queries.sql`; виконуйте запити по одному й переглядайте Data Output.
4. Відкрийте `lab3/oltp.sql`. Для перегляду проміжних результатів виконайте `BEGIN`, потім D1–D11 послідовно в одному Query Tool, включаючи всі контрольні SELECT, і завершіть `ROLLBACK`. Також можна виконати весь файл разом; зміни буде відкочено наприкінці.
5. Виконайте весь `lab3/tests.sql`; очікувані помилки перехоплюються, результати `PASS` видно в Messages.
6. Повторіть `lab3/queries.sql`: початкові дані та кількості мають залишитися незмінними.

Якщо виникла неочікувана помилка всередині транзакції, виконайте `ROLLBACK;` перед повторним запуском.

## Умови демонстрації

ID `1001` і `1002` зарезервовані для навчальних операцій. Дати фіксовані, щоб результат не залежав від дня запуску; Q8 показує прострочення на 25.11.2026. Для перевірки на сьогодні замініть у ньому `DATE '2026-11-25'` на `CURRENT_DATE`.

Видача захищена частковим унікальним індексом із `lab2`. Правило про обов'язкового автора кожної книги, як і в `lab2`, не гарантується самими FK: у демонстрації книгу та авторство додаємо разом, а видаляємо авторство лише разом із самою навчальною книгою.
