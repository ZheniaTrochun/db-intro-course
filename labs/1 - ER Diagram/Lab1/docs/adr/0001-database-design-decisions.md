# 1. Архітектурне рішення: Концептуальна модель даних та первинні ключі для Logistics

## Статус
Прийнято

## Контекст
Необхідно розробити концептуальну схему бази даних (ERD) для системи управління складом та логістикою `logistics`. Схема повинна підтримувати відстеження постачань, локацій та внутрішніх переміщень, а також бути готовою до міграції в PostgreSQL.

## Рішення
1. **Використання UUIDv7 для ключових бізнес-сутностей (`Product`, `Supplier`, `SupplyOrder`, `WarehouseLocation`):**
   - Забезпечує глобальну унікальність без ризику колізій при масштабуванні.
   - Зберігає часову послідовність (time-ordered), що оптимізує індекси B-Tree.
2. **Використання `BIGSERIAL` для транзакційних записів (`SupplyItem`, `InventoryMovement`):**
   - Зменшує розмір зовнішніх індексів для високонавантажених таблиць рухів.
3. **Виділення `SupplyItem` як окремої сутності:**
   - Розв'язує зв'язок багато-до-багатьох між товарами та накладними, фіксуючи закупівельну ціну на момент операції та цільову локацію прийому.

## Наслідки
- Позитивні: Висока узгодженість даних, збереження історії цін на момент постачання, відповідність 3NF.
- Негативні: Додатковий оверхед на збереження 128-бітних UUID у порівнянні зі звичайними цілими числами.
