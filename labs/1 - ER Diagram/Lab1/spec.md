# Сутності

- **Товар (Product):** назва, артикул (SKU), одиниця вимірювання, мінімальний поріг залишку, опис, категорія
- **Постачальник (Supplier):** назва компанії, контактна особа, номер телефону, email, адреса
- **Локація складу (WarehouseLocation):** зона, номер ряду/стелажа/полиці, максимальна місткість
- **Накладна постачання (SupplyOrder):** дата надходження, статус обробки, підсумкова сума, посилання на постачальника
- **Позиція накладної (SupplyItem):** посилання на накладну, посилання на товар, посилання на комірку зберігання, кількість, ціна закупівлі
- **Внутрішнє переміщення (InventoryMovement):** посилання на товар, комірка відправлення, комірка прийому, кількість, дата та час операції

# Унікальні ключі

- **Product:** id (*UUIDv7*), sku_code (*Unique Key*)
- **Supplier:** id (*UUIDv7*), email (*Unique Key*)
- **WarehouseLocation:** id (*UUIDv7*), location_code (*Unique Key*)
- **SupplyOrder:** id (*UUIDv7*), order_number (*Unique Key*)
- **SupplyItem:** id (*BigSerial*)
- **InventoryMovement:** id (*BigSerial*)

# Припущення

- Первинними ключами для основних сутностей обрано UUIDv7 для забезпечення часового сортування та масштабованості розподілених записів.
- Асоціативна сутність `SupplyItem` дозволяє розбити зв'язок багато-до-багатьох між накладною та товарами, одночасно закріплюючи початкове фізичне розміщення партії на складі.
- Поле `total_cost` у `SupplyOrder` дублює суму рядків `SupplyItem` на концептуальному рівні для оптимізації читання аналітичних даних (з подальшою денормалізацією/тригеризацією на етапі фізичної реалізації).
- Якщо партія товару списується або видається за межі складу, `to_location_id` в сутності `InventoryMovement` може приймати значення `NULL`.
- Позиції в накладній `SupplyItem` після отримання статусу `received` не підлягають прямому редагуванню — коригування залишків дозволяється лише через `InventoryMovement`.
