## WorldEntity

Визначає спільні дані між різними сутностями, що існують в ігровому світі. Зважаючи на це, зберігає інформацію про розташування сутності - position_x, position_y, position_z - decimal, zone_id - int, max_hp - int, level - int.

zone_id є foreign key до сутності Zone, кардинальність - нуль чи багато до тільки одного. Кожна WorldEntity закріплена за єдиною зоною, в той час як в зоні можуть бути як нуль, так і багато WorldEntity.

## Zone

Визначає зону ігрової мапи. має атрибути zone_name - varchar[100] - назва зони, а також level_requirement - рівень, досягнення якого необхідно щоб увійти до цієї зони. 

# MonsterEntity

Один з видів сутностей, що "наслідують" WorldEntity. Відповідно є foreign key entity_id int NOT NULL. Також має стан - блукає або атакує (state - enum{wander, attack}), відповідно може зберігати id персонажа, якого атакує (target_id int - foreign key на Character). Також має type_id - int NOT NULL, foreign key на MonsterType. Тип зв'язку нуль або багато до тільки одного, адже кожна одиниця монстра має тип, але необов'язково існують одиниці певного типу монстра. Окрім того, має stats_id - int, foreign key на сутність Stats, тип зв'язку один до одного.

# MonsterType

Статична таблиця для усіх існуючих у грі типів монстрів. Головним ключем цієї сутності є varchar[128] - таким чином кожен тип монстра ідентифікується унікальним рядком, наприклад red_deadly_wolf або scaleless_dragon. Окрім того є окремий атрибут name - varchar[128] для повноцінного імені, що висвітлюється в UI клієнту гри. Також є атрибут description - varchar[500]

Окрім того, кожен тип монстра має один або кілька типів предметів, що з них випадають при вбивстві. Це реалізовано асоціативною сутностю MonsterDrop

## MonsterDrop

Має два атрибути, які є foreign key: monster_id varchar[128] та item_id int. Кардинальність з боку MonsterDrop - нуль або багато, а з боку поєднуваних сутностей - лише один. Сутність MonsterDrop поєднує лише один тип монстра з лише одним типом предмета. При цьому той самий тип предмету може бути дропом кількох різних видів монстрів, а один тип монстра може мати кілька типів предметів, що з нього випадають. Фактично це є деталлю реалізації зв'язку багато до багатьох між MonsterType та ItemType.

## NPC

NPC також "наслідує" WorldEntity. має foreign key entity_id int NOT NULL - один до одного. Також кожен NPC має ім'я - name varchar[128]. NPC має складний спосіб взаємодії з ItemType - для торгівлі кожен NPC повинен мати зв'язок з кожним ItemType - визначати, чи цей торговець торгує даним предметом, і, якщо так, які його ціни на купівлю та продаж цього предмету. Для цього реалізовано асоціативну сутність NPCItemRelation

## NPCItemRelation

Foreign keys - npc_id, item_id - int. Кардинальності - один або багато до лише одного. У цьому випадку ставлення кожного npc має існувати до кожного предмету, тож нуля таких взаємозв'язків бути не може якщо існує хоч один NPC та один ItemType. Окрім того визначає атрибути trades bool, sell_price int, buy_price int
