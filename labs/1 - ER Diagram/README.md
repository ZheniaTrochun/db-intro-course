# Trackly-db-Course

База даних для сервісу трекінгу звичок та управління завданнями Trackly

## Основні функції програми

1. Управління завданнями - планування поточних справ, розстановка пріоритетів та дедлайнів
2. Трекінг звичок - формування рутин, відстеження серій виконання та підтримання регулярності
3. Спільна робота - шеринг завдань з іншими користувачами та командне виконання
4. Аналітика та статистика - перегляд звітів про продуктивність для оцінки прогресу та оптимізації

## Результати аналізу вимог

Trackly - сервіс трекінгу звичок та управління завданнями

### Потреби зацікавлених сторін

#### Індивідуальні користувачі

- Створення та закріплення корисних звичок через регулярні нагадування, розклад та візуалізацію безперервних серій
- Зручне планування щоденних завдань, розстановка пріоритетів та оптимізація робочого часу
- Автоматичний розрахунок дедлайнів і виконання дій з урахуванням часового поясу користувача
- Збереження історії та статистики продуктивності для рефлексії та покращення результатів

#### Командна робота (Workspaces)

- Організація спільного простору для команди чи проєкту
- Розподіл завдань між учасниками, призначення відповідальних виконавців та контроль статусу
- Моніторинг командних дедлайнів, завантаженості та загальних показників прогресу
- Розмежування рівнів доступу

### Концептуальний дизайн

- Сутності: Users, Habits, HabitCompletions, Tasks, Workspaces, WorkspaceMembers, Categories, TaskCategories, HabitCategories
- Атрибути:
  - **Users**: id, name, nickname, phone_number, password, email, timezone, created_at, updated_at
  - **Habits**: id, name, description, frequency_days, creator_id, timezone, status, start_date, end_date, created_at, deleted_at, updated_at
  - **HabitCompletions**: id, habit_id, local_date, completed_at, note, actual_value
  - **Tasks**: id, name, description, timezone, status, priority, creator_id, assignee_id, workspace_id, deadline, created_at, deleted_at, updated_at
  - **Workspaces**: id, name, description, owner_id, created_at, status
  - **WorkspaceMembers**: user_id, workspace_id, role, joined_at
  - **TaskCategories**: task_id, workspace_id, name, color, created_at, deleted_at, update_at
  - **HabitCategories**: habit_id, user_id, name, color, created_at, deleted_at, update_at

#### Бізнес-зв'язки

1. Один User може мати декілька Habits, Tasks, Workspaces
2. У Habits, Tasks, Workspaces може бути лише один творець
3. Одна Category може мати декілька Tasks, Habits

### Бізнес-правила та обмеження цілісності

- Акаунти
  - пошта, нікнейм та номер телефону - унікальні дані
  - облік виконання розраховується щодо часового поясу користувача

- Habits & Completions
  - можливо поставити лише один статус одночасно
  - можливо вказати персональний розклад
  - не доступно для Workspaces
  - підрахунок серії
    - серія продовжується, поки користувач щодня виконує завдання
    - пропущення одного дня скидає поточну серію до нуля
    - дні, що не входять у розклад, не переривають серію

- Tasks
  - дедлайн не може бути раніше створення завдання
  - до завдань які складаються у Workspaces мають доступ тільки учасники цього Workspace
  - зберігає часовий пояс для кожного завдання окремо (можливість вказати інший часовий пояс для певних завдань)

- Workspaces
  - може мати виключно одного творця
  - кожному учаснику надається роль із заздалегідь визначеними правами
  - має бути мінімум один учасник
  - максимум 5 просторів для одного власника
  - не може бути вилучений з Workspace його творець
  - може бути видалено лише творцем
  - заборона видалення акаунту творця до передачі прав власності іншій особі, якщо статус Workspace не "closed" або якщо там ще є інші учасники

- Categories
  - має мати унікальну назву в одного користувача або Workspace
  - при видаленні категорії весь її вміст потрапляє в кошик на 30 днів, для можливості відновлення

### Use Cases

| Сценарій                                | Тип операції    | Вимога                                                                                                                       |
| :-------------------------------------- | :-------------- | :--------------------------------------------------------------------------------------------------------------------------- |
| Реєстрація користувача                  | Create          | Збереження email та нікнейму, фіксація локального часового поясу (timezone).                                                 |
| Оновлення даних облікового запису       | Update          | ---                                                                                                                          |
| Видалення облікового запису користувача | Delete          | Завдання, звички та категорії, які були прив'язані виключно до цього користувача, повинні бути видалені                      |
| Створення завдання                      | Create          | Дедлайн завдання не може бути встановлений у минулому часі.                                                                  |
| Оновлення даних завдання                | Update          | Може змінити лише автор або користувач із спеціальними правами доступу                                                       |
| Створення звички                        | Create          | Встановлення початкової та кінцевої дати, фіксація часового поясу для відстеження розкладу.                                  |
| Відмітка виконання звички               | Create / Update | Фіксація виконання за локальним часом. Допускається лише один статус на день.                                                |
| Пропуск звички                          | Update          | Якщо день за розкладом пропущено, поточна безперервна серія скидається до нуля.                                              |
| Видалення звички                        | Delete          | Видаляються лише наступні повторення, але історія зберігається і не змінюється                                               |
| Створення категорії                     | Create          | Назва категорії повинна бути унікальною в межах одного користувача або робочого простору.                                    |
| Групування звичок/завдань в категорії   | Update          | Прив'язка існуючої категорії до завдання чи звички. Одна сутність може мати декілька категорій (зв'язок багато-до-багатьох). |
| Видалення категорії                     | Soft Delete     | Дані не видаляються безповоротно, а отримують статус deleted_at і зберігаються в кошику 30 днів.                             |
| Видалення завдання                      | Soft Delete     | Отримує мітку deleted_at та переміщається в кошик на 30 днів.                                                                |
| Створення Workspace                     | Create          | Користувач стає власником. Діє обмеження: максимум 5 просторів для одного власника.                                          |
| Призначення завдання в команді          | Update          | Виконавець обов'язково має бути учасником даного робочого простору.                                                          |
| Видалення учасника з Workspace          | Delete          | Фізичне видалення запису з бази, після чого користувач остаточно втрачає доступ до простору.                                 |
| Видалення Workspace                     | Delete          | Може бути видалено лише його творцем                                                                                         |
