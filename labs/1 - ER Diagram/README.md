## Вимоги:

Автоматизоване середовище повинно забезпечувати координацію ринку нерухомості, облік об'єктів, обробку запитів клієнтів та юридичну фіксацію угод оренди між власниками, орендарями та рієлторами.

Для досягнення цих цілей система повинна забезпечувати виконання таких функціональних вимог:

- Управління ролями та персональними данними
- Облік об'єктів нерухомості
- обробка заявок та запитів
- юридичне оформлення та фіксація угод

весь перелічений функціонал також повинні виконувати певні умови:

- підтримувати безпеку персональних данних від сторонніх осіб
- бути оптимізованим для уникнення перенавантаження системи й створенню додаткових витрат
- мати змогу простого маштабування й відлагодження
- забезпечувати простоту у використанні як користувачем так і менеджером

## Опис сутностей:

- Власник :
  - INT | ID власника | PK;
  - VARCHAR | ПІБ;
  - INT | номер телефону;
  - VARCHAR | паспортні дані.
- Орендар :
  - INT | ID орендаря | PK,
  - VARCHAR | ПІБ,
  - INT | номер телефону,
- Рієлтор :
  - INT | ID рієлтора | PK,
  - VARCHAR | ПІБ,
  - INT | телефон,
  - DECIMAL | відсоток комісійних.
- Об'єкт нерухомості :
  - INT | ID об'єкта | PK,
  - INT | ID власника | FK,
  - VARCHAR | адреса,
  - ENUM | статус (доступно/орендовано).
- Заявка :
  - INT | ID заявки | PK,
  - INT | ID орендаря | FK,
  - INT | ID об'єкта | FK,
  - DATE | дата подачі,
  - ENUM | статус (в обробці/схвалено/відхилено).
- Угода оренди :
  - INT | ID угоди | PK,
  - INT | ID об'єкта | FK,
  - INT | ID орендаря | FK,
  - INT | ID рієлтора | FK,
  - DATE | дата початку,
  - DATE | дата закінчення,
  - DECIMAL | сума оренди,
  - DECIMAL | комісія агентства.

## Зв'язки між сутностями:

- Власник — Об'єкт нерухомості (1 : N): Один власник може володіти кількома об'єктами нерухомості, але кожен об'єкт належить лише одному власникові.
- Орендар — Заявка (1 : N): Один орендар може подавати декілька заявок на перегляд або оренду різних об'єктів.
- Об'єкт нерухомості — Заявка (1 : N): На один об'єкт нерухомості може бути подано декілька заявок від різних орендарів.
- Орендар — Угода оренди (1 : N): Один орендар може виступати стороною в кількох угодах оренди (наприклад, у різний час).
- Об'єкт нерухомості — Угода оренди (1 : N): Один об'єкт нерухомості може фігурувати в багатьох угодах оренди протягом усього часу роботи агентства.
- Рієлтор — Угода оренди (1 : N): Один рієлтор може супроводжувати та закривати багато угод оренди.

## Обмеження до системи:

- Унікальність даних: Номери телефонів та email для Власників, Орендарів і Рієлторів повинні бути унікальними в системі.
- Валідація числових значень:
  - Сума оренди та комісія агентства мають бути суворо більшими за 0.
  - Відсоток комісійних рієлтора має перебувати в межах від 0% до 100%.
- Логіка дат: Дата закінчення угоди оренди повинна бути пізнішою за дату початку (`end_date > start_date`).
- Бізнес-правила статусів:
  - Об'єкт нерухомості не може мати двох активних угод оренди на один і той самий період.
  - При укладанні угоди статус об'єкта змінюється на `орендовано`, а відповідна заявка — на `схвалено`.
