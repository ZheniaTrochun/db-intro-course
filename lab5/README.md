# Лабораторна робота № 5 — опис SQL-запитів

Файл `lab5.sql` створює та наповнює базу даних обліку користувачів, гуртожитків, навчальних курсів і заяв на вакансії. Нижче наведено короткі пояснення команд у порядку їх виконання.

## Підготовка бази даних

### Видалення попередньої структури

| Команда | Що робить і навіщо |
| --- | --- |
| `DROP TABLE IF EXISTS … CASCADE` | Видаляє перелічені таблиці та залежні об'єкти, щоб повторно створити структуру. `IF EXISTS` дозволяє виконати команду, навіть якщо таблиць немає. |
| `DROP TYPE IF EXISTS … CASCADE` | Видаляє попередні типи статусів і залежні об'єкти, щоб визначити ці типи заново. |

### Створення типів і таблиць

| Команда | Що робить і навіщо |
| --- | --- |
| `CREATE TYPE student_status` | Визначає допустимі статуси студента: навчається, в академвідпустці, випущений або відрахований. Обмежує можливі значення поля. |
| `CREATE TYPE user_status` | Дозволяє лише статуси користувача `active` і `blocked`, щоб уникнути довільних значень. |
| `CREATE TYPE application_status` | Визначає статуси заяви: `submitted`, `accepted`, `rejected`, щоб фіксувати етап її розгляду. |
| `CREATE TABLE dorms` | Створює довідник гуртожитків з унікальними номерами й адресами для обліку місць проживання. |
| `CREATE TABLE users` | Зберігає особисті дані, унікальну електронну адресу, статус і гуртожиток користувача для спільного обліку студентів та адміністраторів. |
| `CREATE TABLE departments` | Створює довідник кафедр для подальшого закріплення за ними курсів. |
| `CREATE TABLE rooms` | Зберігає кімнати та їхні гуртожитки. Унікальність пари «гуртожиток — номер кімнати» запобігає дублюванню кімнат. |
| `CREATE TABLE students` | Пов'язує студента з користувачем і, за наявності, кімнатою; зберігає рік вступу та статус для обліку навчання і проживання. |
| `CREATE TABLE dorm_admins` | Закріплює адміністратора за гуртожитком. Складений зовнішній ключ вимагає, щоб цей гуртожиток збігався з гуртожитком користувача. |
| `CREATE TABLE parking_slots` | Створює облік паркомісць і їхніх власників. Власник має належати до того самого гуртожитку; після його видалення місце звільняється через `ON DELETE SET NULL (user_id)`. |
| `CREATE TABLE courses` | Зберігає назви курсів і належність до кафедр для організації навчальних дисциплін. |
| `CREATE TABLE enrollments` | Пов'язує студентів із курсами, зберігає дату запису й оцінку. Унікальна пара студента і курсу забороняє повторний запис. |
| `CREATE TABLE vacancies` | Зберігає компанії та назви посад для обліку доступних вакансій. |
| `CREATE TABLE applications` | Зберігає заяви студентів на вакансії, дати й статуси. Забороняє повторну заяву того самого студента на ту саму вакансію. |

### Початкове наповнення

| Команда | Що робить і навіщо |
| --- | --- |
| `INSERT INTO dorms` | Додає чотири гуртожитки для перевірки зв'язків і групування даних. |
| `INSERT INTO users` | Додає десять користувачів, зокрема користувача без гуртожитку, для перевірки вибірок і подальших змін. |
| `INSERT INTO departments` | Додає три кафедри для розподілу курсів. |
| `INSERT INTO rooms` | Додає шість кімнат для розміщення студентів. |
| `INSERT INTO students` | Додає п'ять студентів із різними статусами, зокрема студента без кімнати, для демонстрації вибірок і поселення. |
| `INSERT INTO dorm_admins` | Додає чотирьох адміністраторів для обліку відповідальних за гуртожитки. |
| Перший `INSERT INTO parking_slots` | Додає сім зайнятих паркомісць для перевірки обліку власників і зайнятості. |
| Другий `INSERT INTO parking_slots` | Додає два вільні паркомісця без `user_id` для пошуку та видалення незайнятих місць. |
| `INSERT INTO courses` | Додає чотири курси для перевірки записів студентів і статистики кафедр. |
| `INSERT INTO enrollments` | Додає п'ять записів на курси з оцінкою або без неї для перевірки агрегатів і популярності курсів. |
| `INSERT INTO vacancies` | Додає три вакансії для демонстрації подання заяв і видалення вакансій. |
| `INSERT INTO applications` | Додає чотири заяви з різними статусами для перевірки зв'язків і зміни результатів розгляду. |

## 1. Вибірка даних

| № | Запит | Що робить і чому |
| --- | --- | --- |
| 1.1 | Активні користувачі та їхні гуртожитки | Виводить дані користувачів зі статусом `active`, упорядковані за ID. `LEFT JOIN` зберігає у результаті також користувачів без гуртожитку, щоб список був повним. |
| 1.2 | Студенти, які проживають у кімнатах | Поєднує студентів, користувачів, гуртожитки та кімнати й сортує за гуртожитком і кімнатою. Внутрішні `JOIN` залишають лише записи з усіма відповідними зв'язками для перегляду розселення; статус студента не фільтрується. |
| 1.3 | Вільні паркомісця | Виводить гуртожитки й номери місць із `user_id IS NULL`, щоб знайти доступні місця для призначення користувачам. |

## 2. Додавання даних

| № | Запит | Що робить і чому |
| --- | --- | --- |
| 2.1 | Нова вакансія | Додає вакансію `Trainee Database Developer` компанії `SoftServe`, щоб студент міг подати на неї заяву. |
| 2.2 | Заява студента на вакансію | Додає заяву студента з `user_id = 8` на створену вакансію з поточною датою та статусом `submitted`. Підзапити знаходять потрібні ID для зв'язування записів. |
| 2.3 | Перевірка заяви | Поєднує заяви, студентів, користувачів і вакансії та показує заяви до `SoftServe`, щоб перевірити додавання й дані заявника. |
| 2.4 | Новий користувач | Додає Ірину Левченко до гуртожитку № 4 для демонстрації створення користувача та його подальшого видалення. |
| 2.5 | Перевірка користувача | Шукає доданого користувача за унікальною електронною адресою, щоб підтвердити успішне створення запису. |

## 3. Зміна даних

| № | Запит | Що робить і чому |
| --- | --- | --- |
| 3.1 | Статус заяви до зміни | Показує заяву Івана Петренка до `EPAM`, щоб зафіксувати її початковий статус перед оновленням. |
| 3.2 | Прийняття заяви | Змінює статус заяви студента з `user_id = 1` на вакансію `EPAM` на `accepted`, щоб відобразити позитивний результат розгляду. Підзапити визначають студента і вакансію. |
| 3.3 | Перевірка нового статусу | Повторно виводить заяву цього студента до `EPAM`, щоб перевірити встановлення статусу `accepted`. |
| 3.4 | Призначення гуртожитку | Установлює `dorm_id = 3` користувачу з ID 8, щоб закріпити його за гуртожитком № 3. |
| 3.5 | Призначення кімнати | Установлює `room_id = 5` студенту з `user_id = 8`, щоб поселити його в кімнату 301. |
| 3.6 | Перевірка поселення | Виводить ім'я, прізвище, гуртожиток і кімнату студента, щоб перевірити результат обох оновлень. |

## 4. Видалення даних

| № | Запит | Що робить і чому |
| --- | --- | --- |
| 4.1 | Видалення вакансій Rozetka | Видаляє вакансії компанії `Rozetka`, щоб прибрати їх з обліку. Пов'язані заяви видаляються автоматично завдяки `ON DELETE CASCADE`. |
| 4.2 | Перевірка списку вакансій | Виводить усі вакансії за ID, щоб переконатися у відсутності видалених записів. |
| 4.3 | Видалення користувача | Видаляє Ірину Левченко за електронною адресою для демонстрації видалення користувача без залежних записів. |
| 4.4 | Перевірка видалення користувача | Шукає користувача за тією самою адресою. Порожній результат підтверджує видалення. |
| 4.5 | Видалення вільного паркомісця | Видаляє місце `P-401` лише за умови `user_id IS NULL`, щоб прибрати вільне місце, не зачіпаючи зайнятого. |
| 4.6 | Перевірка видалення паркомісця | Шукає місце `P-401`; порожній результат підтверджує його видалення. |

## 5. Агрегація, з'єднання та підзапити

| № | Запит | Що робить і чому |
| --- | --- | --- |
| 5.1 | Загальна кількість користувачів | Обчислює `COUNT(*)` у таблиці `users`, щоб отримати загальну кількість користувачів після виконаних змін. |
| 5.2 | Середня, мінімальна та максимальна оцінки | Обчислює округлене середнє, мінімум і максимум серед виставлених оцінок для узагальнення успішності. Умова `grade IS NOT NULL` явно відбирає записи з оцінками. |
| 5.3 | Кількість користувачів у кожному гуртожитку | Групує дані за номером гуртожитку й рахує `COUNT(u.user_id)`. `LEFT JOIN` показує також гуртожитки без користувачів із кількістю 0 для повного огляду заселеності. |
| 5.4 | Гуртожитки із зайнятими паркомісцями | За допомогою `SUM(CASE …)` рахує зайняті місця в кожному гуртожитку. `HAVING` залишає лише групи з додатною кількістю, щоб показати гуртожитки, де паркування використовується. |
| 5.5 | Гуртожитки, паркомісця та їхня зайнятість | Виводить номер гуртожитку, номер паркомісця та ID його власника. `RIGHT JOIN` зберігає всі гуртожитки, зокрема без паркомісць, для повного переліку; `NULL` у власника наявного місця означає, що воно вільне. |
| 5.6 | Кількість курсів кожної кафедри | Для кожної кафедри корельований підзапит рахує її курси, щоб оцінити розподіл дисциплін. Кафедра без курсів отримує кількість 0. |
| 5.7 | Курси з більш ніж одним студентом | Підзапит групує записи на курси й відбирає групи з `COUNT(*) > 1`; зовнішній запит через `IN` виводить назви цих курсів, щоб визначити курси з кількома слухачами. |
| 5.8 | Кафедри з кількістю курсів не меншою за середню | Рахує курси кожної кафедри й через `HAVING` порівнює кількість із середнім із вкладеного підзапиту, щоб знайти кафедри з відносно великою кількістю курсів. Середнє обчислюється лише серед кафедр, які мають хоча б один курс, оскільки підзапит групує таблицю `courses`. |

Описи відповідають послідовному виконанню всього `lab5.sql`: підсумкові вибірки враховують попереднє додавання, оновлення та видалення даних.
