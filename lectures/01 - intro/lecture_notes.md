## Важливість баз даних

### Чому база даних критично важлива:

1. Центральна роль в системах
   - База даних - це серце будь-якої складної системи
   - Повноцінний бекенд-додаток не може функціонувати без БД

2. Критичність для кар'єри
   - Ключова частина технічних співбесід
   - На бекенд-позиції ~20-30% співбесіди присвячено обговоренню тем пов'язаних з БД
   - Без фундаментальних знань БД складно знайти хорошу роботу, особливо у сфері серверної (бекенд) розробки

3. Академічне значення
   - Фундаментальні знання, необхідні для успішного проходження багатьох подальших курсів
   - 30-50% вступного іспиту на магістратуру присвячено БД (практико-орієнтовані завдання: побудова схем, написання запитів)

4. Універсальність
   Знання і навички роботи з БД корисні не тільки для бекенду, а й для майже всіх інших сфер розробки програмного забезпечення

## Основні поняття

### База даних vs Система управління базами даних (СУБД)

База даних:
- Організований набір даних
- Моделює певний процес, об'єкт чи аспект реального світу
- Приклади: список групи, книга контактів, тощо

Система управління базами даних (СУБД / DBMS):
- Софт для роботи з базами даних
- Забезпечує гнучку та ефективну роботу з даними
- Приклади: PostgreSQL, MongoDB, MySQL

> **Примітка:** В розмовній мові обидва поняття часто називають просто "база даних"

### Проблеми зберігання даних у файлах

При зберіганні даних у звичайних файлах (наприклад, CSV) виникають серйозні проблеми:

#### 1. Проблеми з ефективністю
- Повільна робота при великих обсягах даних
- 4 записи читаються швидко, тисячі записів - повільно
- Складні операції пошуку та з'єднання даних

#### 2. Проблеми консистентності даних
- Можливість "мертвих посилань"
- Приклад: курс видалений, але студенти залишились записаними на нього
- Відсутність контролю цілісності даних

#### 3. Проблеми надійності (ACID: Atomicity, Consistency, Isolation, Durability - детально в лекції 10)
- Що робити при збоях системи?
- Приклад: студент записався, курс не записався через відключення електрики
- Неможливість гарантувати атомарність операцій

#### 4. Відсутність стандартизації
- Кожна система має власний формат
- Складність міграції між системами
- Відсутність уніфікованого інтерфейсу

### Переваги СУБД

Системи управління базами даних вирішують ці проблеми:

1. Консистентність даних - контроль цілісності та зв'язків
2. Ефективність - оптимізована робота з великими обсягами даних
3. Надійність - механізми відновлення після збоїв
4. Уніфікований інтерфейс - стандартизовані мови запитів, які базуються на стандарті SQL
5. Автоматизоване управління - СУБД керує файлами самостійно

### Стандарт SQL

Реляційна модель була запропонована Едгаром Коддом (IBM) у 1970 році, а стандарт SQL існує з 1986 року як стандарт ANSI та ISO з 1987 року.  
Всі сучасні реляційні СУБД базують свої мови запитів на стандарті SQL, тому базові запити виглядають однаково в PostgreSQL, MySQL, Oracle та інших реляційних СУБД.   

Проте це не означає, що вони реалізують стандарт однаково: частина ключових слів та конструкцій відрізняється між СУБД.
Тому запит, який правильно працює в PostgreSQL, може не працювати в MySQL, Oracle чи інших СУБД.
Наприклад, у PostgreSQL є конструкції `INSERT ... RETURNING` та `INSERT ... ON CONFLICT`, яких немає в стандарті і які в MySQL чи Oracle записуються інакше або відсутні взагалі. Ми познайомимось з ними більш детально на 4-й лекції.

## Типи DBMS

### 1. Реляційні бази (SQL)
- Приклади: PostgreSQL, MySQL, Oracle, MS SQL Server
- Особливості: підтримують стандарт SQL, структуровані таблиці
- Найпоширеніший тип на сьогоднішній день

### 2. Документо-орієнтовані бази
- Приклади: MongoDB, CouchDB, Couchbase
- Особливості: зберігають дані у форматі JSON
- Гнучка структура: немає чіткої схеми

### 3. Бази даних "ключ-значення"
- Приклади: Redis, Memcached
- Найпростіший тип: працюють як великий словник
- Використання: кешування, сесії, тощо

### 4. Спеціалізовані бази даних

#### Векторні бази
- Застосування: семантичний пошук, машинне навчання, Data Science

#### Графові бази
- Особливості: зберігають дані та відношення між ними
- Застосування: картографія, соціальні мережі

#### Колонкові бази
- Приклади: ClickHouse, Snowflake
- Застосування: аналітика, робота з величезними наборами даних, Data Warehouse
- Особливість: ефективні складні запити на великих обсягах даних

#### Бази даних для часових рядів (Time Series)
- Приклади: InfluxDB
- Застосування: метрики, дані з датчиків, дані, що базуються на часі
- Особливість: ефективна робота з великими часовими рядами та вибірками на основі часових інтервалів

### Тренди у розвитку баз даних

- Реляційні бази додають можливості роботи з документами
- В той же час багато NoSQL баз рухаються в сторону SQL. Наприклад, MongoDB додала JOIN'и та транзакції (хоч і наразі доволі обмежені за можливостями)
- Рух до універсальності: різні типи БД запозичують функції один у одного, проте фундаментальні відмінності все одно залишаються

### Архітектура: клієнт-серверні та вбудовані СУБД

Незалежно від моделі даних, СУБД відрізняються тим, як саме вони запускаються та як з ними працює програма:

Клієнт-серверні СУБД:
- СУБД - окремий процес (зазвичай на окремій машині), застосунок спілкується з ним по мережі
- Приклади: PostgreSQL, MySQL, Oracle, MongoDB, Redis
- Плюси: багато клієнтів одночасно, централізований контроль доступу, масштабування, СУБД повністю відділена від застосунку

Вбудовані (embedded) СУБД:
- СУБД - як бібліотека всередині застосунку; а сама база даних - це просто файл на диску сервера чи клієнта, де запускається застосунок
- Приклад: SQLite - найпоширеніша реляційна СУБД у світі: є в кожному Android та iOS, у Chrome і Firefox, у більшості десктопних програм
- Плюси: нуль адміністрування, один файл, нічого не потрібно запускати додатково
- Мінуси: один процес, що записує дані в БД, немає мережевого доступу до БД

Практичне правило: мобільний або десктопний додаток, локальний кеш - варто використовувати SQLite (або іншу вбудовану СУБД); бекенд - зазвичай клієнт-серверна СУБД.

У даному курсі обрано саме PostgreSQL, тому що ця СУБД строго типізована (на відміну від SQLite), має значно ширший функціонал, підтримує багато одночасних записів і є типовим вибором для бекенд-застосунків.

## Інструменти курсу

### Основна СУБД: PostgreSQL
Чому PostgreSQL:
- Одна з найкращих реляційних баз даних на сьогоднішній день
- Багатий функціонал та висока ефективність
- Одна з найрозповсюдженіших СУБД на даний момент
- Повністю open source та безкоштовна
- Має детальну документацію та багато повʼязаних ресурсів у вільному доступі

### Інтерфейс: pgAdmin
- Візуальний інтерфейс для роботи з PostgreSQL
- Зручна візуалізація схем БД
- Зручна робота з SQL запитами
- Альтернативи: DataGrip (JetBrains), DBeaver, тощо. В межах курсу можна використовувати будь-який інший візуальний інтерфейс або TUI/CLI, якщо Ви надаєте перевагу іншому інструменту.

### Контейнеризація: Docker
- Використання для зручного розгортання середовища
- Стандартизація робочого середовища для всіх студентів 

> **Примітка**: У продакшені СУБД найчастіше працюють на виділених серверах або як керовані хмарні сервіси (Amazon RDS, Cloud SQL тощо). Контейнери в продакшені теж використовують (наприклад, Kubernetes-оператори для PostgreSQL), але це вимагає експертизи та обережного налаштування сховища та ресурсів. У межах курсу та для тестових оточень Docker - найпростіший спосіб підняти СУБД, тому ми будемо користуватись саме ним.

Детальніше про роботу з Docker розповідається на 2-й лекції.
